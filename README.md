# Crew Manifest Fix

Small fixes for [Crew Manifest](https://github.com/linuxgurugamer/CrewManifest) 6.5.1.1.

Forum thread: https://forum.kerbalspaceprogram.com/topic/231954-112x-crew-manifest-fix-020-no-duplicate-toolbar-buttons-a-close-button-no-log-spam/

## Duplicate toolbar buttons

Reported upstream as [linuxgurugamer/CrewManifest#1](https://github.com/linuxgurugamer/CrewManifest/issues/1).

`CrewManifest.ManifestBehaviour` is declared as `[KSPAddon(KSPAddon.Startup.Flight, false)]` and calls `DontDestroyOnLoad` on itself in `Awake`. KSP creates a new instance on every flight scene load, and the old ones are never destroyed. Each instance adds its own toolbar button and keeps running `Update`/`OnGUI` every frame, so after a few vessel switches you get several identical buttons, extra CPU work and `NullReferenceException`s from `ManifestController.drawGui` in the log.

A Harmony prefix on `ManifestBehaviour.Awake` keeps the first instance and destroys every later one before it adds a button — the behaviour `once: true` would have given.

## Close button

The Crew Manifest window could only be closed with its toolbar button. A Harmony prefix on `ManifestController.ManifestWindow` draws a "×" button in the window's top right corner. It calls Crew Manifest's own toolbar handler, so the toolbar icon follows, and turns the stock toolbar button off, so the next toolbar click opens the window again.

## Log spam

The window function logs `Crewmanifest, vessel: ...` on every GUI event while the window is open — about 15% of all `KSP.log` lines in a session, and each one costs CPU time. A Harmony transpiler removes that one `Debug.Log` call.

## Notes

Crew Manifest's own files are not modified, so reinstalling or updating it through CKAN does not undo the fixes.

Crew Manifest is resolved at runtime. If it is missing or changed, the fix logs a warning to `KSP.log` and does nothing. It is also harmless if Crew Manifest gets fixed upstream.

## Requirements

- KSP 1.12.x
- Crew Manifest **exactly 6.5.1.1** — the fix is written for this release only. On any other version it logs a warning to `KSP.log` and does nothing.
- Harmony 2.2.1 or newer (`000_Harmony`)

## Installation

- **CKAN:** search for "Crew Manifest Fix" (once it is indexed).
- **By hand:** download the zip from [Releases](https://github.com/genyk1p/CrewManifestFix/releases) and copy `GameData/CrewManifestFix` into the game's `GameData` folder. Install Harmony 2 as well if you do not have it yet.

Safe to add to or remove from an existing save: the mod saves nothing.

## Building

```
dotnet build src -c Release
```

The KSP install path defaults to the Steam location; override it with the `KSPDIR` environment variable or `-p:KSPDIR=...`.

## По-русски

Исправляет баг Crew Manifest 6.5.1.1: при каждой загрузке полёта мод создавал ещё одну свою копию и ещё одну кнопку на тулбаре, а старые не удалялись. Фикс оставляет только первую копию. Кроме того, у окна Crew Manifest появился крестик «×» в правом верхнем углу, а строка «Crewmanifest, vessel: …», которую мод писал в лог каждый кадр, пока окно открыто, больше не пишется. Файлы Crew Manifest не изменяются, поэтому переустановка через CKAN фикс не ломает.

Мод написан в соавторстве с **Claude Code** (Anthropic), модель **Claude Opus 5.5**: код, конфиги и документацию сгенерировал ИИ, автор задал идею и требования, проверил архитектуру и протестировал в игре.
